## New findings spotted during verification

### [R2-1] Crash-recovered in-flight calls are permanently unbookable through the sanctioned lifecycle (P2, related to LEDGER-2 but distinct)
- Evidence (all repro'd): after any crash mid-call, the recovered manager marks the reservation `pending_reconciliation` (reservation-manager.ts:1620-1648 dangling scan) while the call index still shows state `'reserved'` (the index never saw a settle). From that state:
  - `settleCall` -> `manager.settle` throws `INVALID_SETTLEMENT_STATE` (reservation-manager.ts:740-745 — `pending_reconciliation` is not `active|interim_settled`); repro passed.
  - `reconcileLateUsage` -> `LATE_USAGE_BEFORE_TERMINATION` (two-phase.ts:695-701 — index state `'reserved'`); repro passed.
  - The ONLY sanctioned exit is `bookNewAttempt`, which books the usage as a NEW settled call under a fresh callId while the original `pending_reconciliation` buffer stays locked forever (nothing releases it) — i.e. the sanctioned crash-recovery path is exactly the LEDGER-1 double-charge surface plus a permanent fund lock in enforce mode.
- Why not covered by LEDGER-2: LEDGER-2 is the WAL/index divergence window; this fires even when WAL and index are fully consistent — it is a state-machine gap between the manager's recovery states and the two-phase guard, with no recovery scan that back-fills or advances the index identity.
- Fix direction: on `recoverFromWal`, sync the call index from replayed state (or teach `reconcileLateUsage`/`settleCall` to accept the `index='reserved' && manager='pending_reconciliation'` combination as reconcilable).

### [R2-2] `bookNewAttempt` silently books 0 when no rate card is reachable (P3)
- Evidence (observed while building repro 1a): `bookNewAttempt` derives `estimatedCostMicros: origin?.reservedCostMicros ?? 0` (two-phase.ts:755) and passes `rateCard = origin?.rateCard ?? event.rateCard` (:750); with an unreachable origin and no card in the event, `beginCall` reserves 0 and `settleCall({outcome:'failed', usage})` falls to the reserved-upper-bound branch (reservation-manager.ts:861-881), booking `totalCostMicros = 0` for real usage. Same root cause as LEDGER-3's branch (no-card fallbacks), on the new-attempt path. Repro run showed `settledMicros=0` for two attempts before the rate card was added.
